## 买之前先定三件事

### 一、Java 版还是基岩版

两个版本都有官方服务端，生态差别很大。Java 版的插件和模组是开服的主要玩法来源；基岩版覆盖手机、Windows 和主机玩家，但服务端侧的可定制性弱得多，跨版本插件 Geyser 的兼容性也随版本漂移，官方支持页给出的范围是 Java 26.2 配 Bedrock 26.30–26.52，其他 Java 版本还要额外挂 ViaVersion。

基岩版的网络配置比 Java 版麻烦。Java 版一直只监听 TCP 25565，一条规则搞定。基岩版自 Bedrock 26.50（首个服务端构建 1.26.51）起，NetherNet 成了专用服务器的默认传输，路由器上要放行 TCP 19132 再加一段 `server-udp-ports` 指定的 UDP 端口；想回到经典配置，就在 `server.properties` 里写 `transport=raknet`，只放行 UDP 19132。

如果只是想和几个朋友联机、完全不想碰配置，Mojang 官方的 Realms 是另一条路：订阅制，按档位支持 3 人或 11 人同时在线，只有受邀玩家能进，不用记 IP。代价是 Java 版的 Realms 不能和基岩版玩家跨平台，也不能装插件和模组。

### 二、原版、插件服还是模组服

三条路互斥，装错 jar 后面全白费：

- **原版 `server.jar`**：最干净，性能一般，加不了模组
- **Paper**：原版基础上做了性能优化，支持 Bukkit 系插件，是插件服的事实标准
- **Fabric / Forge**：要装模组只有这两条路，原版 jar 加不了

### 三、租云还是自己搭

有闲置电脑、只跟固定几个人玩，可以本机开服再用内网穿透暴露出去。缺点是电脑不能关、家宽上行通常只有几 Mbps，超过三五个人就会卡。租云的月成本在几十元这个量级，省下的是折腾时间和稳定性。

## 服务端选型：Paper 还是 Fabric、Forge

要插件选 Paper，要模组选 Fabric 或 Forge，两个都要就得在功能上做取舍。

Paper 在 2014 年 6 月 23 日从 Spigot 分叉出来，起因是 Spigot 当时不太愿意接收社区贡献。它后来的性能改进幅度很大，插件生态也跟着长起来了。截至 2025 年 6 月，社区指标平台 bStats 记录到同时运行超过 13 万台 Paper 服务器，占 Bukkit 生态全部服务端实现的 60% 以上。这个占比意味着你遇到的绝大多数开服问题，网上都有人踩过。

顺带说清楚 Bukkit 和 Spigot 今天为什么没人提了。Bukkit 项目在 2014 年 8 月 24 日由 EvilSeph 宣布终止，紧接着 9 月 5 日，贡献者 Wolvereness 向 GitHub 发出 DMCA 下架通知，因为 Bukkit 里包含了 Mojang 的专有代码，波及 Bukkit 及其分支（包括 Spigot）。此后这条线再没更新过。所以今天说“插件服”，实际指的就是 Paper。

走模组路线有几条硬规则，违反任何一条都会出现“装了没反应”：

- 必须先装 **Fabric-API**，不装它，其他模组一个都不会生效
- 模组分服务端模组和客户端模组。小地图这类客户端模组不用上传服务器，本地装了就能用；连锁采集这类服务端模组，本地和服务器两端必须保持完全一致
- 最省事的做法是本地 mods 文件夹和服务器 mods 文件夹内容一模一样

## 从零到能进服：六步走完，五个坑绕开

流程本身不复杂，卡人的永远是细节。以下按 Ubuntu 系统、面板机之外的裸机部署讲。

1. 更新系统：`sudo apt update && sudo apt upgrade -y`
2. 装 JDK。版本跟着服务端版本走：1.19 时代用 OpenJDK 17，1.21.1 配 JDK 21，更新的 26.3 按 Mojang 的版本元数据需要 Java 25。装完 `java -version` 确认一下
3. 下载服务端 jar 并放进服务器目录
4. 写启动脚本，示例 `java -Xmx7G -Xms7G -jar paper.jar nogui`。`-Xmx` 是最大内存，`-Xms` 是初始内存，按机器实际内存调，别把整机内存全给 Java
5. 首次启动会生成 `eula.txt`，把 `eula=false` 改成 `eula=true`。这是 Mojang 的硬性要求，不改服务器起不来
6. 编辑 `server.properties`，`server-port=25565`、`server-name`、`motd` 按需填，再启动一次

五个最容易卡住的地方：

**端口没放行。** 客户端连不上，第一件事查防火墙有没有放行 25565（或你自定义的端口）。云厂商的安全组和系统防火墙是两套，两边都要开。

**换了存档起不来。** 替换 `world` 文件夹后，如果服务是用非 root 的专用用户（比如 `mcfabricuser`）跑的，新目录的属主还是旧用户，服务端没有写权限。执行 `sudo chown -R mcfabricuser:mcfabricuser /minecraft` 就能起来。另外替换时文件夹名必须仍然叫 `world`。

**CentOS 7 装不了 MCSManager。** 面板会直接提示操作系统版本过低。只用命令行的话 CentOS 7 还能跑，想用面板就换 Ubuntu 24.04 LTS 或 CentOS 8 以上，Ubuntu 更省事。

**面板和命令行的选择。** MCSManager 提供文件管理、上传、服务端配置、事件任务、应用实例设置这些图形化功能，换存档和传模组在网页上点两下就完事，比 SSH 里 `rm -rf` 加 `mv` 安全得多。

**内存参数照抄。** 别人 8GB 机器写 `-Xmx7G`，你 2GB 机器也照抄，服务端直接起不来。内存参数必须和套餐配置对上。

## 常见问题

**5 个人玩，4GB 内存够吗？**
够。原版或轻插件，2 核 4GB 能稳住 5 到 8 人。装了十几个插件、开了视距 10 以上，就得往 8GB 走。

**Paper 和 Fabric 能一起用吗？**
不能，同一个服务端 jar 只能是一种实现。要插件选 Paper，要模组选 Fabric 或 Forge，二选一。

**为什么提示 Outdated client 或 Outdated server？**
客户端和服务端版本不一致。`Outdated client` 是服务端比客户端新，玩家要更新游戏；`Outdated server` 是服务端落后于客户端，得换对应版本的服务端 jar。基岩版更麻烦一点，微软明确提醒过连补丁版本都可能改网络协议，玩家端自动更新之后服务端往往要跟着升。

**换了存档之后服务器起不来怎么办？**
先看属主。非 root 用户跑的服务，替换 `world` 后必须 `chown` 给那个用户；确认文件夹名还是 `world`；还不行就直接用 root 跑一次启动命令，看报错信息。

**插件装哪？模组装哪？**
插件扔 `plugins` 目录，模组扔 `mods` 目录，别混。模组还要求本地和服务端一致，插件不需要玩家本地装。

**面板机还需要自己开端口吗？**
NAT 模式的机型通常要在面板里手动做一次 25565 的端口转发，照着面板提示走两三步。独立 IP 的机型在安全组放行即可。
